# SengenWinUI3 の設計

この文書は、SengenWinUI3 の層・公開する型の契約・部品の範囲・性能の判断を、今の形で書く設計正本である。実装と食い違ったら、同じ変更の中でこの文書を直す。節「進み具合」だけは、作業の途中の状態を書く節であり、作業を終えたら消す。

## 命令が決めたこと

この節は、この作業(ONE.O.NET の issue #12 の「やることの1」)の命令が決めた境目と禁止を、理由とともに写す。兵士・検査員・参謀長は命令でなくこの文書を読むため、ここに写さない禁止は届かない。

| 決めたこと | 理由 |
|---|---|
| 式は本物の部品(画面に実際に出る WinUI の部品のオブジェクト)を直接組む。設計図(部品の種類と設定の値だけを持つ軽いデータの木)と差分の層は作らない | SengenUI も本物を直接組んでおり、差分の計算は作る費用と更新の費用の両方を足すため |
| 件数の多い一覧だけ、見えている行だけを作って使い回す部品(`ItemsRepeater` と自前の `IElementFactory`)で書く。使い回しにする境目は判断9で決めた | 全部の行を本物で作ると、行数に比例して作る時間とメモリが増えるため |
| SengenWinUI3 は WinUI の部品をそのまま返さず、自前の型で包んで返す(包む費用の判断は判断1) | 利用する側が WinUI を直接触れないようにし、ONE.O.NET の規約(`csharp_coding_rules.md` 第9条の4)をコンパイラで守るため |
| 実行中に変わる値は、利用する側が部品の `Set〜` へ渡す。値の入れ物と購読は核に置かない | 核には WinUI 3 の薄い包みと部品の寿命だけを置くため |
| 書き方の細部は SengenImgui の形に合わせる(型を保つ拡張メソッドのチェーン・`Tap`・`return ( ... )`・`sealed` の単位のクラス・静的な条件は `?:` と null・名前付きの見た目の定数と `With`)。名前は日本語にする(後にオーナーの裁定で英語へ変わった。判断16) | オーナーが SengenImgui で決めた書き方であり、ONE.O.NET の命名の規約に合わせるため |
| ONE.O.NET のコードを見ずに、WinUI 3 の薄い包みとして一般に必要な部品をそろえる。それより後に足りないと分かったものは、使われた形から足す | オーナーの指示(ONE.O.NET の issue #12 の1)。利用する側から逆算すると、一般の形でなく1つのアプリの形になるため |
| 段の順番を、(1) 共通の契約と見本、(2) 将軍への設計の確かめ、(3) 部品の幅を広げる、に固定する。性能は測らず、実行の仕組みから判断する(オーナーの決定) | 部品の数より契約のほうが、後の置き換えの書き味と費用を決めるため |
| 核から消したもの(値の入れ物・結ぶ仕組み・UI スレッドへ送る仕組み・`If`・トースト)は、ONE.O.NET の #12 の PR では ONE.O.NET に入れず、ONE.O.NET の #16 段bで最初の呼び出し元と同じ変更で入れる(将軍が採った外れ) | オーナーの決定は核の上を ONE.O.NET の中に置くことであり、置く時期を最初の呼び出し元と同じ変更にしても決定に反しない。呼び出し元の無い実装を main に入れないため。元のコードはコミット `63650c9` から取れる |
| 回帰テストは足さない | 命令の指定 |
| リポジトリは公開である。PC の構成を書かない | PC と個人を特定できる情報を公開のリポジトリに書かないため |


## ONE.O.NET の規約から外れる所

SengenWinUI3 の C# の規約の正本は ONE.O.NET の `.claude/規約/コード/` にある。次の5か所は、オーナーが SengenUI と SengenImgui で決めた書き方に合わせるため、その規約の文から外れる。規約の文を直すのは、ONE.O.NET の画面を SengenWinUI3 へ置き換える任務で ONE.O.NET の側で行う。

| 規約の条 | 外れる所 | 理由 |
|---|---|---|
| `csharp_coding_rules.md` 第5条の1(null を「無し」の意味に使わない) | 子の配列の中の null を飛ばす(判断5)。`Style` の項目は全部 null を許し、null は「当てない」を表す | SengenImgui の `守るべきテクニック.md` 第5条・第6条・第8条の書き方であり、構築の時に決まる条件を `condition ? node : null` の1つの式で書くため |
| 第6条の3と第9条の1(画面の木を `new` と初期化子の入れ子の式で書く) | 画面の木を、葉を作る関数と型を保つ拡張メソッドのチェーンで書く | SengenUI と SengenImgui の書き方であり、オーナーが「メソッドチェーンなどは同じにしたい」と決めたため |
| 第13条の3(材料から値を作る静的メソッドは `From〜`) | 葉の部品を作る関数の名前を、部品の型の名前と同じにする(`TextBlock("…")`) | 判断4。この関数は値の型を作る関数でなく、画面の木を書くための語であるため |
| 第4条の1(検証つきの値は `sealed class` と `Try〜` の結果の `union`) | `Ratio`(0〜1)は `readonly record struct` にし、範囲の外はコンストラクタが例外を投げる | 利用する側が `Style` の定数の中で `new Ratio(0.5)` と書くためである。範囲の外の値は書いた側の誤りであり、到達したらバグとして扱う |
| 第13条の9と `命名.md`(日本語の識別子を基本にし、英語は許可した語だけ) | 公開する名前を英語にし、WinUI 3 にある部品は WinUI 3 の名前にする(判断16) | オーナーの裁定(2026-11-07)。汎用のライブラリであるため |

## 目的

SengenWinUI3 は、WinUI 3 の画面を C# の式で組む薄いライブラリである。利用する側は、部品の木を式で組み、出来事を処理へつなぎ、表示を変えるときは `Set〜` を呼ぶ。値の入れ物と購読、条件表示やトーストは利用する側が自分で書く。

## 層の定義

SengenWinUI3 は部品の層の1つのプロジェクトだけを持つ。利用する側から部品の層へ参照し、部品の層から利用する側は参照しない。

| 層 | プロジェクトと名前空間 | 持つもの | 知ってよいもの |
|---|---|---|---|
| 部品 | `src/SengenWinUI3/`(`net11.0-windows`)。名前空間 `SengenWinUI3` | 部品の型と作る関数・型を保つチェーン・Style と当て方・値の型・WinUI 3 の薄い包み・親子と破棄 | .NET と WinUI 3 |
| 利用する側 | このライブラリを参照するアプリ | 画面の単位・状態・サービス・値の入れ物・購読と結ぶ仕組み・UI スレッドへ送る仕組み・条件の出し分け・トースト・ウインドウごとの状態 | 部品の層の公開 API とアプリ自身の型 |

核から削除した値の入れ物などは、利用する側が自分で書く。部品のプロジェクトは状態のプロジェクトを参照せず、利用側の型も参照できない。部品の本物は internal に閉じ、外からは `Component` だけを継承できる。

部品の名前空間を1つにするので、利用する側は `using SengenWinUI3;` と `using static SengenWinUI3.UI;` の2行で全部を使える。

## 主要な設計判断

### 判断1: すべての部品は自前の基底 `Node` を継承した包みの型である

`Node` とは、画面の木に入れられるものすべての基底の型のことである。`Node` は本物の WinUI の部品を1つ持ち、その本物を `internal` でしか見せない。利用する側は、SengenWinUI3 が作った部品の本物へ触れる手段を持たない。`Node` のコンストラクタは `private protected` にし、SengenWinUI3 の外からは `Component`(判断2)だけを継承できる。

包む型で守れるのは、SengenWinUI3 が作った部品の本物へ触れないことだけである。利用する側はアプリの `Window` を持つため WinUI のパッケージを参照しており、WinUI の部品を自分で `new` する書き方はコンパイルで止まらない。それを止めるには、利用する側のプロジェクトに使うと警告になる API を列挙する解析器(`Microsoft.CodeAnalysis.BannedApiAnalyzers`)を入れる。これは置き換えの任務へ申し送る。

包む費用は、部品1つにつき管理されたオブジェクト1つ(と小さな台帳)である。WinUI の部品そのものを作る費用は、ネイティブのオブジェクトの生成・管理された側との対の包み(CsWinRT の参照)・木への登録・配置と描画の計算であり、包む費用はこれに比べて小さい。このため、測らずに包む型で決めた(オーナーの決定)。

`TextBlock` と `Border` は WinUI の側で `sealed` であり継承できないので、葉の部品(本物を1つだけ持つ部品)は、継承でなく本物を持つ形で包む。継承できる WinUI の部品も、同じ形にそろえる。

### 判断2: 利用する側の画面の単位は `Component` の `sealed` の派生であり、根は初めて木へ入れるときに作る

`Component` とは、ほかの部品を組み合わせて1つの単位にした部品の基底のことである。派生のクラスは `protected override Node Build() => ( ... );` で中身の木を返す。`Component` は `Build()` を基底のコンストラクタから呼ばず、本物が初めて要ったとき(親の木へ入れるとき)に1回だけ呼ぶ。基底のコンストラクタから仮想メソッドを呼ぶと、派生のフィールドが初期化される前に派生の処理が走るためである(SengenImgui の `設計思想.md` 8.2 と同じ規律)。

`Component` は自分では WinUI の部品を増やさない。親の木へ入るのは `Build()` が返した部品の本物である。構造だけの部品を1段増やすと、繰り返す行で費用が掛け算になるためである。`Component` に当てたチェーンの設定(余白・見た目など)は根の本物に当たり、根を構築した後に当てたものが効く。

C# の null 許容参照型を有効にしているので、`Build()` の中で `Tap` を使ってフィールドへ部品を受ける書き方は、フィールドが null 許容になり成り立たない。後から更新したい子は、フィールドの初期化子で作って持ち、木の中にそのフィールドを置く。引数に依存する子は、主コンストラクタ(`sealed class 名前(引数) : Component`)の引数をフィールドの初期化子で使って作る。これは SengenUI の「裸の部品をフィールドで持たず、拡張の型にする」規則とも合う。

### 判断3: チェーンは型を保つ拡張メソッドで書く

全部の部品に共通の操作(`Style`・`Tap`・`Own`・出来事の `On〜`)は、`public static T Style<T>(this T node, Style style) where T : Node` の形の拡張メソッドにする。T を受けて T を返すので、具象の型を保ったままチェーンを書ける。見た目の項目は `Style` にまとめる。

一部の種類の部品だけが持つ設定は、その種類が実装する目印のインターフェースを制約に足した拡張メソッドにする(`where T : Node, IHasChildren`)。目印のインターフェースの中身は `internal` にし、SengenWinUI3 の外からは実装できない形にする。1種類の部品だけが持つ設定は、その部品の型のメソッドにする。

### 判断4: 葉の部品は型と同じ名前の関数で作り、複合部品は `new` で作る

葉の部品と `VirtualList` は静的クラス `UI` の関数で作る。関数の名前は部品の型の名前と同じにし、コンストラクタは internal にする。利用する側の `Component` の派生は `new SlotCard(…)` の形で作る。

この分け方は、SengenUI のガイド第5条(LV1 は糖衣の関数で作り、LV1 拡張は `new` で作る)と、SengenImgui の `UI.cs`(`Text("…")`・`VStack()` を `using static` で取り込む)の2つの前例と同じである。型と同じ名前の関数を `using static` で取り込んでも、型の宣言と関数の呼び出しを同じファイルに並べてコンパイルが通ることを、固定した SDK で確かめた。

### 判断5: 子は配列で受け、null を飛ばす

子を持つ部品の `Children(params Node?[] children)` は配列の null を飛ばす。構築時の条件は `condition ? node : null` で書く。実行中の条件の出し分けは利用する側が書く(判断8)。

### 判断6: 値の入れ物と購読は利用する側が書く

核は固定の初期値と `Set〜` を受ける。核は値の入れ物を持たず、値の変化を購読しない。利用する側が購読と表示への反映を書き、必要なら購読を解く資源を `node.Own(resource)` で部品の寿命へ預ける。

核の公開の操作は全部 UI スレッドで呼ぶ。別のスレッドから UI スレッドへ送る処理と、送った後に部品が破棄された場合の扱いは、利用する側が書く。

### 判断7: 子の覚えと破棄のたどり方は基底の `Node` が1か所で持つ

`Node` は親と子の List を覚える。部品が子の本物を `Panel.Children`・項目のコレクション・中身・浮かぶ部品・`Component` の根のどこへ入れても、基底の internal の操作で登録する。破棄ではこの子の List だけをたどる。

外す操作は2つだけにする。`Detach()` は今の親から外すだけで、購読は残す(別の親へ入れ直せる)。`Destroy()` は、自分と子孫の購読を解き、子孫の覚えを捨て、破棄を始めた部品だけを親の本物から外す。子孫の本物は、破棄を始めた部品の本物ごと木から外れるので、1つずつ外さない。1つずつ外すと、子の数の2乗の手間になりうるためである。2回目の `Destroy()` は何もしない。破棄した後の部品へのほかの操作は、到達したらバグである状態として例外を投げる。親を持つ部品を別の親へ入れたときも例外を投げる。WinUI の部品は親を1つしか持てず、黙って外すと、どこで付け替えたかがコードから読めなくなるためである。

利用する側は、タイマー・購読・木に入れていない部品・浮かぶ部品を `node.Own(…)` へ預けられる。部品の破棄で資源は Dispose され、預けた部品は Destroy される。利用する側でも解く資源は、Dispose を2回呼んでも害の無い形にする。`window.SetContent(node)` は、閉じたときに根を破棄する。

### 判断8: 実行中の条件の出し分けは利用する側が書く

核から `If` と `ConditionalPresenter` を削除した。利用する側は `Component`・子の追加・`Detach()`・`Visible(bool)` を組み合わせて、条件で見せる部品を替える。木に入れていない部品の寿命は `Own(Node)` で預けられる。部品を作る時期と、見せない部品を保持するか破棄するかも、利用する側が決める。

### 判断9: 件数の多い一覧は `VirtualList` で書き、行は作るときに1回だけ配線する

`VirtualList<TItem, TRow>` とは、ItemsRepeater を包んで見えている行だけを作り、外れた行を使い回す部品のことである。利用する側は行を作る関数を渡し、行は Component と IRecyclableRow を実装する。一覧は Show(item) で項目を渡し、使い回しの待ちへ入るときと破棄時に Release() を呼ぶ。行の作者は Show で Set〜 を呼ぶ。項目に結び付いた資源がある場合、行の作者は Release で解く。核は行の購読を持たない。

行の部品は作ってから一覧の破棄まで一覧の子であり、行だけを外す操作は無い(`Detach`・`Destroy` を行に呼ぶと例外)。`SetItems` は項目の集まりを作り直して `ItemsSource` を差し替える。1件ずつ足すと件数の回だけ知らせが飛ぶためである。作る関数は `VirtualList<TItem, TRow>(createRow)` で、型引数は2つとも書く。`VirtualList` はスクロールを中に持たず、外側の `ScrollViewer` の部品の中に置く。`ItemsRepeater` は外側のスクロールの見えている範囲で仮想化するので、中にスクロールを持つと、スクロールする画面の中に置いたときに2重のスクロールになるためである。末尾へ移ることと末尾に留まることは、`ScrollViewer` の部品が持つ。外側のスクロールの中で使い回しが効くことは、見本のアプリで 10000 件を出して確かめた(作った行は始めに 80、末尾まで移った後に 106)。`ScrollViewer` を `StackPanel` の中に置くと高さが無限になり使い回しが効かないので、一覧を入れた `ScrollViewer` は高さの決まる所に置く。

使い回された行は別の項目を見せるので、行の配線は作るときに1回だけ行い、行がいま見せている項目の ID をハンドラへ渡す(`on削除(ID)`)。行ごとの ID をラムダで捕まえる書き方は使えない。一覧は、項目を私有の箱の型に包んで `ItemsSource` へ渡す。項目が構造体でも、WinRT の境目を値のまま越えずに済ませるためである。

件数に上限の無い一覧(会話の履歴など)は、件数によらず `VirtualList` で書く。上限があり件数の少ない一覧は、子を持つ部品の `AddChild`・`child.Destroy()` と、利用する側の `Dictionary<ID, 行>` の手動の管理で書く(SengenUI と同じ)。件数が決まっていて少ない一覧は、全部の行を作る。件数に上限が無いか、利用する側のデータで件数が増える一覧は、件数によらず `VirtualList` で書く。境目は測らずに、件数が決まっているかで決めた(オーナーの決定)。

### 判断10: 見た目は名前付きの定数で共有し、当て方は部品の種類ごとに持つ

`Style` とは、背景・文字の色・文字の大きさ・文字の太さ・枠線・角の丸み・内側の余白などを、全部 null を許す項目で持つ値のことである。null の項目は当てない。利用する側は `static readonly Style` の定数を並べ、`With(上書き)` で派生を作る。`Style` がブラシ(WinUI が色を塗るときに使うオブジェクト)を作るのは、初めて部品へ当てるときに1回だけであり、同じ定数を当てた部品は同じブラシを共有する。色の項目の型は `union Brush(Color)` にする。後でテーマの色(明るい表示と暗い表示で替わる色)を `Brush` の場合に足しても、利用する側の定数を書き直さずに済ませるためである。

`Style` を当てる道は2つある。1つは、葉の部品を作る関数の最後の省略できる引数(`StackPanel(Styles.Card)`・`TextBlock("見出し", Styles.Title)`)である。旧アプリの SengenUI の `div({ class: styles.root })` と同じ書き味にするためである(オーナーの決定。2026-11-07)。もう1つは、後から当てる `.Style(...)` である。作る関数で渡した `Style` は、作った直後に `.Style(...)` と同じ当て方を1回呼ぶだけにし、2つの道で結果が食い違わないようにする。`Component` は利用する側がコンストラクタを書くので、基底は `Style` の引数を持たず、後から `.Style(...)` で根へ当てる。

当て方は、`Node` の `internal virtual` の操作(案: `ApplyStyle(Style)`)を部品の種類ごとに上書きして、その部品のファイルが持つ。部品を1種類足すときに、ほかの部品のファイルを書き換えずに済ませるためである。部品が持たない項目(`TextBlock` の背景など)が null でない `Style` を当てたら、到達したらバグである状態として例外を投げる。書いた見た目が黙って効かないと、利用する側は理由をコードから読めないためである。`Component` に当てた `Style` は根へ渡す。どの項目がどの部品に効くかは README に表で書く。

### 判断11: 長さは `Px` の型で渡す

`Px` とは、WinUI が大きさと位置に使う単位(画面の拡大率で物理の画素へ換算される前の画素。英語で effective pixel)の長さを持つ値の型のことである。公開の関数は、幅・高さ・余白・間隔・文字の大きさを `double` でなく `Px` で受ける。ONE.O.NET の規約(`csharp_coding_rules.md` 第2条の3)が、単位の分からない `double` を境界の外へ渡さないと定めているためである。書き味を保つため、`12.Px` と書ける拡張のプロパティを `int` と `double` に持つ。`int` から `Px` への暗黙の変換は置かない。余白は `Thickness` の値で `Style` に入れ、`Thickness` は `new Thickness(8.Px)`(4辺同じ)・`new Thickness(縦, 横)`・`new Thickness(左, 上, 右, 下)` の3つの作り方を持つ。色は自前の `Color` の型で、寄せ方と向きは自前の列挙で渡す。利用する側が WinUI の型(`Microsoft.UI.Xaml.Thickness`・`Windows.UI.Color`・`Microsoft.UI.Xaml.HorizontalAlignment`)を書かずに済ませるためである。

### 判断12: 木へ入れられないポップアップは `FloatingNode` にし、チェーンで部品に付ける

`Popup` は本物が FrameworkElement でも木へ入れずに使うため FloatingNode とする。`Flyout` と `MenuFlyout` は `FrameworkElement` でなく、`ContentDialog` は木へ入れずに出し、`ToolTip` は添付プロパティで部品に付ける。どれも画面の木の子にならないので、`Node` を継承させない。`FloatingNode` とは、木へ入れられず、ほかの部品に付けて出す部品の基底のことである。中身は `Node` で受け、浮かぶ部品の破棄で中身を破棄する。付け方は部品のチェーンにする(`Flyout(flyout)`・`ContextFlyout(menu)`・`ToolTip("…")`)。確認の画面は、基準の部品から表示に要る `XamlRoot` を取る `ShowAsync(Node anchor)` で出し、結果を `union` で返す。

### 判断13: 出来事は `On〜` で1つの部品に1回だけ受け、引数に WinUI の型を出さない

葉の部品の出来事は `OnClick(Action handler)` の形で受け、自分の型を返す。同じ部品の同じ On〜 への2回目の登録は例外になる。全部の部品に共通のキー・ポインタ・大きさ・読み込みと取り外しの出来事はチェーンで受け、引数に WinUI の型を出さない。

値を見せる部品は初期値と Set〜 を受け、本物の今の値と等しい値を再設定しない。入力する部品と選ぶ部品の On〜Changed は、利用者が値を変えたときだけ呼ぶ。プログラムからの Set〜 では呼ばない。部品の実装は Set〜 の間の変更通知を抑え、例外が起きても finally で抑制を戻す。複数の値を設定する操作でも、抑制は設定全体を囲む。

### 判断14: ウインドウへは拡張メソッドで置く

利用する側は、アプリの `Window` に `window.SetContent(node)` で根の部品を置く。2回呼ぶと、前の根を破棄して置き換える。

### 判断15: トーストとウインドウごとの状態は利用する側が書く

核からトーストの実装を削除した。トーストとは、画面の隅へ一時的に出す知らせのことである。利用する側は、浮かぶ部品・文字・ボタン・動きの薄い包みを組み合わせてトーストを書く。文言・時間・積む向き・上限・通知の重複の扱いは利用する側が決める。

`WindowHost` は根を持ち、閉じたときに根を破棄するだけである。核はウインドウごとの状態をここへ追加しない。

### 判断16: 公開する名前は英語にし、WinUI 3 にある部品は WinUI 3 の名前にする

オーナーの裁定(2026-11-07)で、SengenWinUI3 は汎用のライブラリなので、公開する型・部品を作る関数・チェーンのメソッド・引数・プロジェクト・名前空間の名前を英語にする。`internal` の型とメンバー(節「部品の内側の約束」の `ContentSlot`・`AdoptChild` など)も英語にする。単位をまたいで部品を書く者が使う内側の約束であり、公開の名前と同じ語の並びで読めるようにするためである。`private` の名前と局所の変数・コメント・文書の文は日本語にする。名前は次の順で決める。

1. WinUI 3 に同じ部品がある部品は、WinUI 3 の名前をそのまま使う(`TextBlock`・`Button`・`Border`・`Grid`・`Image`・`ScrollViewer`・`StackPanel`・`TextBox`・`CheckBox`・`ComboBox`・`Flyout`・`MenuFlyout`・`ContentDialog`)。部品を作る関数も同じ名前にする。並べる向きは、WinUI 3 と同じく `StackPanel` の設定であり、`Style` の `Orientation` で決める
2. チェーンと子の付け方の名前は SengenImgui と同じにする(`Tap`・`Style`・`With`・`Children`・`OnClick`)。見た目は項目ごとのチェーンにせず `Style` のクラスの項目にし、項目の名前は WinUI 3 のプロパティの名前にする(`Margin`・`Padding`・`Width`・`HorizontalAlignment`・`Orientation`・`Spacing`・`Opacity`)
3. WinUI 3 に無い型は一般に通じる英語にする(`Node`・`Component`・`VirtualList`・`Px`)。VirtualList は、行を使い回す一覧であることを名前で示す。

前の版にあった `見出し`・`小見出し`・`縦にスクロールする画面` は、部品として持たない。文字の大きさと余白と最大の幅を決めただけの組み合わせであり、汎用のライブラリが1つのアプリの見た目の値を持つことになるためである。利用する側は、名前付きの `Style` の定数(SengenImgui の `XxxStyles.cs` の形)と `ScrollViewer` と `StackPanel` の組み合わせで書く。

利用する側の画面のファイルは WinUI の名前空間(`Microsoft.UI.Xaml`・`Microsoft.UI.Xaml.Controls`)を `using` しない。`Style`・`TextBlock` などが自前の型と衝突するためである。`Window` を扱うアプリのファイルだけが WinUI の名前空間を使う。

|---|---|
| 部品・複合部品・浮かぶ部品 | `Node`・`Component`・`FloatingNode` |
| 宣言(葉を作る関数の静的クラス) | `UI` |

| 子を入れる・子を足す・子を差し込む・子を全部破棄する・I子を持てる | `Children`・`AddChild`・`InsertChild`・`DestroyChildren`・`IHasChildren` |
| 縦の並び・横の並び | `StackPanel`(向きは `Style` の `Orientation`) |
| 文章 | `TextBlock` |
| 見出し・小見出し・縦にスクロールする画面 | 部品として持たない(上の段落) |
| スクロール | `ScrollViewer`(`ScrollToEnd`・`StickToEnd`) |
| ボタン・画像 | `Button`・`Image` |
| 使い回す一覧・I使い回せる行(項目を見せる・項目から離れる) | `VirtualList<TItem, TRow>`・`IRecyclableRow<TItem>`(`Show`・`Release`) |

| 横の寄せ方・縦の寄せ方 | `HorizontalAlignment`・`VerticalAlignment` |

## 境目の契約

この節は、単位をまたいで使う型と関数の形を決める。公開の型に加え、全部の部品が従う `internal` の約束(節「部品の内側の約束」)も境目に入る。単位の内側の細部(フィールド・私有の関数・内部の型)は、書く兵士が決める。公開する名前は判断16で決め、私有の名前とコメントは日本語でよい。

### 部品の層の基底

```csharp
namespace SengenWinUI3;

public abstract class Node
{
    private protected Node();
    public void Detach();  // 今の親から外す。資源は解かない
    public void Destroy(); // 後片付けと子孫の破棄。2回目は何もしない
}

public abstract class Component : Node
{
    protected Component();
    protected abstract Node Build(); // 初めて本物が要ったときに1回だけ呼ばれる
}

public abstract class FloatingNode
{
    private protected FloatingNode();
    public void Destroy();
}

public static partial class UI { /* 部品ごとのファイルに作る関数を置く */ }
```

利用する側は全部の公開の操作を UI スレッドで呼ぶ。核は別のスレッドへ処理を送らない。`Own` は `Component` の protected メソッドでなく、すべての `Node` に使える型を保つ拡張メソッドである。派生のコンストラクタ内でも `this.Own(resource)` と書く。

`UI` は partial にするので、後の書き手は自分の部品の作る関数を自分のファイルへ追加できる。

### 部品の内側の約束

全部の部品が従う `internal` の約束である。後の単位の兵士は、この形と `src/SengenWinUI3/Text/TextBlock.cs`・`Text/UI.TextBlock.cs`・`Core/UI.cs` を見本に写す。

| 約束 | 決めた形 |
|---|---|
| 本物 | `Node` の `internal abstract WinUI.FrameworkElement Element { get; }`。`Component` は `internal sealed override` で、根を `Lazy<Node>` で初めて読まれたときに `Build()` して返す |
| 台帳 | `Node` は3つの台帳を持って委譲するだけにする。`NodeFamily`(持ち主と子の List)・`CleanupList`(後片付けの対象。先に外せる札を返す)・`EventWiringMarks`(受けた出来事の名前) |
| 持ち主 | internal の `IChildOwner { void AdoptChild(Node child, Action 本物へ入れる); void ReleaseChild(Node child); }`。`Node`・`FloatingNode`・`WindowHost` が明示的に実装する |
| 子の登録 | `Node.AdoptChild(child, 本物へ入れる)` は、破棄済みかを確かめた後、`child.BecomeChildOf(this, 本物へ入れる)` で、子が親を持たないかを確かめ、本物へ入れ、持ち主を覚える。その後に子の List へ足す。本物へ入れるのに失敗したら登録しない。子の台帳を持たない持ち主は `BecomeChildOf` だけを呼ぶ。親の本物から外す方法は `internal virtual void RemoveChildElement(Node child)` で、子を登録する部品は必ず上書きする |
| 外せない子 | `IChildOwner.ThrowIfCannotRelease(child)`(既定は何もしない)。`Node` は `internal virtual ThrowIfChildCannotLeave(child)` へ渡す。`NodeFamily.LeaveOwner` と `Node.Destroy` が、状態を変える前に呼ぶ。外せない子を持つ部品(`VirtualList` の行・`Component` の根)は、これを上書きして例外を投げる |
| 本物を別の仕組みが入れる子 | `AdoptChildPlacedElsewhere(child)` で登録だけする(`Component` の根・`VirtualList` の行) |
| 中身を1つ持つ部品 | 葉は `private readonly ContentSlot 中身置き場 = new(this, 中身の本物 => 本物.Content = 中身の本物)` を持つ。中身は作る関数で受けて `中身置き場.SetContent(content)` で置き、公開の `SetContent(Node)` で入れ替える。入れ替えは、新しい中身を置いた後に前の中身を破棄する。`RemoveChildElement` は `中身置き場.Release(child)`。台帳を持たない持ち主は、自分の破棄で `DestroyContent()` を呼ぶ。`ScrollViewer`・`Button`・`Flyout`・`WindowHost` と、後の `Border` がこの形である |
| 子を何個でも持つ部品 | `IHasChildren` の internal の `ChildCount`・`InsertChildElement(int, Node)`・`ClearChildElements()` を明示的に実装する。子を外す処理は `Node.RemoveChildElement(Node)` を上書きする。拡張メソッドが AdoptChild で登録するので、実装は本物への挿入・削除だけを行う |
| 値を見せる部品 | `ElementValue<TTarget, TValue>`(設定する先・本物と等しいか・本物へ設定する)を持つ。作る関数と公開の Set〜 は Set へ渡す。本物の今の値と比較し、値のコピーは持たない。比べ方と設定は static のラムダで渡す |
| 出来事 | `WireEvent(nameof(On〜), () => 本物.X += 出来事の処理, () => 本物.X -= 出来事の処理)`。2回目は例外にし、解く処理を後片付けへ入れる。出来事の処理の先頭で `if (!IsDestroyed)` を書く。この確かめが止めるのは、破棄の途中に本物から呼び込まれる場合だけである(解く処理は破棄で必ず走る)。型の違う処理を1つの入口で包めないので、出来事ごとに書く。出来事でない1回だけの配線は `MarkWiredOnce(name)` |
| 後片付け | `OwnDisposable(IDisposable)` は破棄で解き、`OwnRemovable(IDisposable)` は先に外せる札を返す。公開の Own は前者を使い、浮かぶ部品を付ける内側の処理は後者を使う。利用側でも解く資源の Dispose は2回呼ばれても害の無い形にする |
| 破棄 | `Destroy()` は、親から外す処理・後片付け・`internal virtual void OnDestroying()`・子孫の破棄を全部行い、起きた例外は `CollectedExceptions` で `AggregateException` にまとめて投げる。子孫の本物は外さない。`DestroyAllChildren` と `FloatingNode.Destroy` も同じ形である。`internal bool IsDestroyed`・`internal void ThrowIfDestroyed()`。公開の操作とチェーンは全部、最初に破棄済みを調べる |
| UI スレッド | 核の公開の操作は全部 UI スレッドで呼ぶ。別のスレッドからの送りと反映の寿命は利用する側が書く |
| 見た目 | 葉は `StyleTarget<本物の型>` を static readonly で持ち、ApplyStyle はその Apply を呼ぶ。当て方は `IStyleGroup<in TElement>` で受け取る本物の型に対して反変である。共通の群は FrameworkElementStyle.Layout と PanelStyle.Background にあり、ControlStyle・BorderStyle・GridStyle・FontIconStyle・ShapeStyle は All を持つ。SymbolIcon は FrameworkElementStyle.Layout と IconElementStyle.Foreground を組み合わせる。持つ項目の印は群から作り、Component は根へ渡す |
| ウインドウ | `ConditionalWeakTable<Window, WindowHost>` で根の持ち主を保持する。WindowHost は ContentSlot と Closed での根の破棄だけを持つ。ウインドウごとの状態は利用する側が書く |
| 目印 | `IHasChildren`・`IClickable`(Flyout を付ける・外す)・`IControlNode { internal WinUI.Controls.Control Control { get; } }`。どれも葉が明示的に実装する |
| 浮かぶ部品 | `FloatingNode` は `AttachTo(anchor, 付けた先から外す)`・`ThrowIfAttached()`・`internal abstract OnDestroying()`・`private protected abstract ReleaseContent(Node)` を持ち、中身は `ContentSlot` で持つ。付けた先の後片付けへ「先に外せる札」で自分の `Destroy` を入れる。浮かぶ部品だけを破棄すると、付けた先から外し、札も外す。付けずに作った浮かぶ部品は、利用する側が `Destroy` するか `Own` で預ける |
| 作る関数と Style | `UI` の共通の部分(`Core/UI.cs`)に `private static T StyleIfGiven<T>(T node, Style? style)`。渡されたときだけ `node.Style(style)` を呼ぶので、後から `.Style` で当てた結果と食い違わない |
| WinUI の名前 | `using WinUI = Microsoft.UI.Xaml;` の別名を使い、`WinUI.Controls.TextBlock` のように書く。衝突しない名前空間はそのまま取り込む |

`Style` に項目を1つ足すときに書き換えるのは、`Style.cs`(項目・`With`・`SpecifiedItems` の3か所)・`StyleItems.cs`(印を1つ)・その項目を当てる `〜Style.cs`(当て方の群を1つ)の3つのファイルである。

`Style` の項目のうち、どの部品がどれを持つかは次のとおりである。持たない項目が null でない `Style` を当てると例外になる。

| 部品 | 持つ項目 |
|---|---|
| 全部の葉 | 幅・高さ・最小最大・Margin・HorizontalAlignment・VerticalAlignment・Opacity |
| `StackPanel` | 上に加え Padding・Background・BorderBrush・BorderThickness・CornerRadius・Orientation・Spacing |
| `TextBlock` | 上(全部の葉)に加え Padding・Foreground・FontSize・FontWeight・FontFamily・TextWrapping・IsTextSelectionEnabled |
| `Button`・`ScrollViewer` | 全部の葉に加え Control の項目(Padding・Background・Foreground・BorderBrush・BorderThickness・CornerRadius・FontSize・FontWeight・FontFamily・HorizontalContentAlignment・VerticalContentAlignment) |
| `Image` | 全部の葉の項目だけ |
| 後の `Grid` | 全部の葉に加え Padding・Background・BorderBrush・BorderThickness・CornerRadius・RowSpacing・ColumnSpacing |
| 後の `Border` | 全部の葉に加え Padding・Background・BorderBrush・BorderThickness・CornerRadius |
| 後の `Canvas` | 全部の葉に加え Background |
| 後の `FontIcon` | 全部の葉に加え Foreground・FontSize・FontWeight・FontFamily |
| 後の `SymbolIcon` | 全部の葉に加え Foreground。大きさは Width・Height で指定する |
| 後の図形 | 全部の葉に加え Fill・Stroke・StrokeThickness |

中身を1つ持つ部品は、作る関数で Node を受け、SetContent(Node) で前の中身を破棄して入れ替える。IHasChildren は Panel に限らず、ListView・ComboBox・RadioButtons の項目にも使う。項目は Node で受け、本物の項目コレクションへ child.Element を入れる。TextWrapping は自前の列挙(NoWrap・Wrap)である。

### 見た目のクラスとチェーンの拡張メソッド(全部の部品)

見た目(大きさ・余白・揃え・並べる向き・間隔・不透明度・色・文字・枠線)は、項目ごとのチェーンのメソッドにせず、SengenImgui の `Style` と同じく、全部 null を許す項目を持つクラスに入れ、`.Style(...)` で当てる(判断10)。CSS の `flex-direction` と同じく、`StackPanel` の並べる向きも `Style` の項目である。

```csharp
public sealed class Style
{
    // 置き方: Width・Height・MinWidth・MaxWidth・MinHeight・MaxHeight(Px?)・Margin・Padding(Thickness?)・HorizontalAlignment・VerticalAlignment(?)
    // 並べ方: Orientation(Orientation?)・Spacing(Px?)
    // 色と文字: Background・Foreground・BorderBrush(Brush?)・BorderThickness(Thickness?)・CornerRadius(Px?)・FontSize(Px?)・FontWeight(FontWeight?)・TextWrapping(TextWrapping?)・IsTextSelectionEnabled(bool?)・Opacity(Ratio?)
    // 追加: RowSpacing・ColumnSpacing(Px?)・HorizontalContentAlignment(HorizontalAlignment?)・VerticalContentAlignment(VerticalAlignment?)・FontFamily(string?)・Fill・Stroke(Brush?)・StrokeThickness(Px?)
    public Style With(Style overlay); // overlay の null でない項目で上書きした新しい Style を返す
}

public static T Style<T>(this T node, Style style) where T : Node;  // 同じ部品に2回当てると、後の Style の null でない項目で上書きする
public static T Tap<T>(this T node, Action<T> action) where T : Node;
public static T Own<T>(this T node, IDisposable resource) where T : Node;
public static T Own<T>(this T node, Node detachedNode) where T : Node;
public static T Own<T>(this T node, FloatingNode floatingNode) where T : Node;
public static T Visible<T>(this T node, bool visible) where T : Node; // 見た目でなく、実行中に変わる表示の状態として持つ
public static T OnSizeChanged<T>(this T node, Action<ViewSize> handler) where T : Node;
public static T OnKeyDown<T>(this T node, Action<KeyInput> handler) where T : Node;
public static T OnLoaded<T>(this T node, Action handler) where T : Node;
public static T OnUnloaded<T>(this T node, Action handler) where T : Node;
public static T OnPointerEntered<T>(this T node, Action<PointerInput> handler) where T : Node; // OnPointerExited・OnPointerPressed・OnPointerReleased も同じ形
public static T ToolTip<T>(this T node, string text) where T : Node;
public static T ContextFlyout<T>(this T node, MenuFlyout menu) where T : Node;
```

- 項目の正確な名前と型は「基底と葉」の単位の兵士が決め、WinUI のプロパティの名前にそろえる。`Style` の値の項目は、`static readonly Style` の定数で共有することを前提に、初期化子で書ける形(`new Style { Margin = …, Spacing = 8.Px }`)にする
- `Style` は1つの部品の型でなく、全部の部品が受ける1つの型である。部品が持たない項目が null でない `Style` を当てたら例外を投げる(判断10)
- `IsEnabled(bool)` と `Focus()` は、本物が `Control` の部品だけが実装する目印のインターフェース(案: `IControlNode`)の制約で置く。使えるかどうかは見た目でなく状態であるため、`Style` に入れない。`Visible` も同じ理由で `Style` に入れない
- `ViewSize`・`KeyInput`・`PointerInput`・`Ratio`・`FontWeight` の形は「基底と葉」の単位の兵士が決め、WinUI の型を出さない

`OnLoaded` と `OnUnloaded` は登録を1回だけ受け、本物の出来事が起きるたびに処理を呼ぶ。2回目の登録は例外になる。部品の破棄で登録を解く。利用する側は `OnUnloaded` を破棄の通知として使わず、後片付けを `Own` へ預ける。`Detach` は破棄ではなく、再び読み込まれる場合があるためである。

後の部品の書き手は、共有の `Style.cs`・`StyleItems.cs` を変更せず、用意した当て方を選ぶ。幅と高さ・最小最大・枠線・角の丸み・背景・文字の色は既存の項目を使う。Grid の間隔・Control の中身の寄せ方・フォント・図形の塗りと輪郭も、この単位で With と未対応項目の検出までそろえた。

### 子を持つ部品

```csharp
public interface IHasChildren { /* 中身は internal */ }

public static T Children<T>(this T parent, params Node?[] children) where T : Node, IHasChildren;      // null を飛ばして末尾へ足す
public static T Children<T>(this T parent, IEnumerable<Node?> children) where T : Node, IHasChildren;
public static T AddChild<T>(this T parent, Node child) where T : Node, IHasChildren;
public static T InsertChild<T>(this T parent, int index, Node child) where T : Node, IHasChildren;
public static T DestroyChildren<T>(this T parent) where T : Node, IHasChildren;
```

子を1つ捨てるのは `child.Destroy()`、別の親へ付け替えるのは `child.Detach()` の後に新しい親へ入れる。`StackPanel()` は WinUI 3 と同じく既定で縦に並べる。横に並べることと子の間の間隔は、`Style` の `Orientation` と `Spacing` で決める(`StackPanel().Style(Styles.Toolbar)`)。既定の値は WinUI 3 と同じにする。

内側の実装の見本は `Layout/StackPanel.cs` である。

```csharp
int IHasChildren.ChildCount => 本物.Children.Count;
void IHasChildren.InsertChildElement(int index, Node child) => 本物.Children.Insert(index, child.Element);
void IHasChildren.ClearChildElements() => 本物.Children.Clear();
internal override void RemoveChildElement(Node child) => _ = 本物.Children.Remove(child.Element);
```

項目を持つ ListView・ComboBox・RadioButtons の書き手は、上の Children を Items に置き換える。同じ部品は Node で受け、登録と破棄は基底へ任せる。AddChild は ChildCount の位置へ InsertChildElement で挿入し、InsertChild は位置を確認してから AdoptChild を呼ぶ。DestroyChildren は登録済みの子を破棄し、ClearChildElements で本物をまとめて外す。

これらの項目を持つ部品は ItemsSource と項目の使い回しを持たない。選択の初期の範囲は1つを選ぶ形であり、未選択と選択済みの位置を区別する自前の型で受け渡す。選択の知らせも Set〜 では呼ばず、利用者の変更だけを On〜Changed で知らせる。

### 葉の部品の形

- 葉の部品の型は `public sealed class 名前 : Node` で、本物を1つ持ち、コンストラクタは `internal` にする。作る関数は `UI` に置き、関数の名前は型の名前と同じにする(`UI.TextBlock("…")` が `TextBlock` を返す)。作る関数は、最後に省略できる `Style? style = null` の引数を持つ(判断10)
- 値を見せる部品は固定の初期値を受ける関数と Set〜 を持つ。核は値の変化を購読しない。
- 入力の部品と選ぶ部品は初期値、Set〜、On〜Changed(Action<T>) を持つ。On〜Changed は利用者の変更だけを知らせ、Set〜 では知らせない。
- 出来事は判断13のとおり `On〜` で受ける。名前は WinUI の出来事の名前に `On` を付けたものにする(`OnClick`・`OnTextChanged`)
- 毎フレームや一覧の行の更新のたびに走る処理では、ラムダ・配列・文字列を作らない。組む時だけ走る処理は気にしない

## この段階でやらないこと

- 設計図と差分の層を作らない。命令の決定であり、差分の費用を引き受けないためである
- 部品の表で外した部品を作らない。一般の形を決める材料が無く、使われた形から足すためである
- XAML のリソースの辞書(テーマの色)の読み込みを包まない。ONE.O.NET の規約が XAML をリソースの辞書に使うことを許しており、テーマの色をどう渡すかは使われた形から決めるためである
- 回帰テストを足さない。命令の指定である
